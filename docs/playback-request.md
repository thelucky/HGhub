# 播放请求适配（2026-11-09）

## 原因

源站当前播放器不再依赖公开详情或旧 GET 播放接口中的 `video_url`。这些字段可能为空，网站另行 POST 获取播放源。网站使用独立的加密播放通道，清单与分片还可能要求 CDN 鉴权。仅修复旧接口的 404 或更换播放器不能完成这一适配。

## 实现

- `playback.rs` 按当前网站公开脚本的协议，以 P-256 ECDH、HKDF-SHA256、AES-256-GCM 完成握手和取址。每次取址使用独立会话和密钥，校验响应的版本、会话、序号、时间与认证标签。POST 不自动重放，不跟随重定向。
- `api_play` 将主播放源与 CDN 配置注册到 Rust 内存，前端只接收随机上下文编号组成的本地播放地址。请求期间线路或账号变化会丢弃返回结果。
- 媒体代理为子清单、密钥和分片保留上下文，按配置对相应扩展名添加 CDN 头；只对主播放源的同一 HTTPS origin 发送这些头，跨站重定向不携带凭据。原有 URL、DNS 和重定向安全检查继续生效。
- 上下文最多保留 64 项、一小时；视频分片恢复浏览器私有缓存（`private, max-age=3600`），主/子清单、密钥和错误响应保持 `no-store`。登录、注册、退出或切换线路时清除已有播放上下文。CDN 头只保存在后端内存中。
- Feed 切集、重新进入条目和点击重试时重新取址；失败不再只调用空播放器的 `play()`。重试已有播放内容时尽量恢复当前进度。切换页面的暂停状态继续由现有播放器生命周期处理。
- 错误提示的“关闭”只关闭遮罩，不清理缓存、不重新取址、不销毁播放器；同一播放源重复报错时不立即重新弹出。用户仍可回看播放器保留的缓冲内容。主动“重试”仍会重新取址。分片 HTTP 缓存是否命中取决于 WebView，应用没有新增完整剧集离线缓存，也不保证保留播放器已淘汰的缓冲。

## 验证

离线 Rust 回归覆盖加密响应的会话/序号匹配、篡改检测、握手有效期、媒体凭据的 origin 隔离、请求头注入拒绝、上下文在嵌套地址中的传递及失效处理。

`cargo test --manifest-path src-tauri/Cargo.toml --lib media::tests::live_play_chain -- --ignored --nocapture` 显式验证真实源站：一次加密取址、一份清单、一个 AES-128 密钥和首个分片。默认测试不联网，不记录直链、凭据或内容。此项通过说明传输链路可用，不等于所有内容和平台都已验证。

`yarn test:playback --scenarios retry,seek,lifecycle` 使用本地生成媒体，验证首次取址失败后点击重试会再次请求并恢复播放，同时检查跳转、后台暂停和手动暂停状态保留。该测试使用 Chromium 与模拟业务接口，不能替代 macOS WKWebView 实机确认。

当前改动适配短剧的 `api_play`；帖子独立取址、其他业务接口迁移和网站后续协议变化不在本次范围。
